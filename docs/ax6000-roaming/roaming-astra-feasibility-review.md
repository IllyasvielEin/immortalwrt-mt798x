**AX6000 漫游方案：Astra 独立可行性审查**

2026-11-08。审查对象为 [A–F 草案](/home/illya/workspace/router/ax6000/research/roaming-options-proposal.md)、根因与社区调研文档、两轮本地证据、精确 7.6.7.3 原始源码及相关本地补丁。本轮仅新增本报告；未联网、未操作路由器、未改配置或固件、未构建或运行测试、未启动子代理。以下实验与验收要求均为后续讨论建议，不表示已经实施或取得实施批准。

**建议采用两条不同的推进顺序：低成本缓解有条件先试 A；长期修复与因果验证优先 B。** 当前不能立即将 A 认定为“已有可用配置”：源码实际依赖外部 `iwpriv`，Build 19 未选中提供它的 `wireless-tools`。B 的机制依据更直接，但仍有授权边界、实际交桥路径和动态切换语义需要落实。C 是可接受继续中断时的退路；D 应由实测性能问题驱动；E 取决于可信跨 AP 事件及原子关联身份检查；F 是有独立迁移成本的替代路线。没有一个方案目前可以称为本机已验证永久修复。

**根因结论可以保留，但应明确是“已观测流量的直接阻断机制”。**

第一轮原始日志在 16:46:42 仍显示目标 SYN-ACK 命中旧 WCID 4、同 wdev、`to_os=0/to_air=1`，16:46:44 老化删除，16:46:51 相应回包变为 `lookup-miss/to_os=1/to_air=0` 并出现在 `wan`。第二轮在 k/v/r=0/0/0 时，两条漫游后的新连接仍重复相同错误分支；删除后新的 SYN-ACK 经 `wan`，用户确认业务恢复。代码的同 wdev 决策与上送条件直接解释了这些记录。因此，“旧关联条目使本地无线回包绕过正确 FDB”有充分依据；不必为了保持审慎而退回“只是猜测”。

证据见 [第一轮原始路径记录](/home/illya/workspace/router/ax6000/research/evidence/roam-20261108-163317/final-recovered/driver-final-ring.log:463)、[对应 wan 回包](/home/illya/workspace/router/ax6000/research/evidence/roam-20261108-163317/final-recovered/tcp-wan.log:444)、[第二轮失败汇总](/home/illya/workspace/router/ax6000/research/evidence/roam-k-off-20261108-1735/failure-summary.json)及[恢复汇总](/home/illya/workspace/router/ax6000/research/evidence/roam-k-off-20261108-1735/recovery-summary.json)。匹配依据是四元组及 seq/ack，而非只有时间相邻。第一轮 16:46:51 回包后是旧连接 RST，只能证明路径恢复；业务恢复须另取后续新连接及用户反馈。

草案已正确保留以下未决点，主线程合稿时应继续保留：

- 尚不知道离网管理帧是否发送、是否到达 AX、是否在插桩之前丢失。未见指定日志不证明终端、GS7 或 PMF 有错。GS7 桥表与用户观察支持位置变化，但该轮 `iw station dump` 没有独立确认目标关联。
- `SST_ASSOC` 是驱动状态，不是客户端仍物理留在该 AP 的证明。独立 AP 暂存旧关联可能符合寿命策略；问题是转发仍把它视为唯一出口依据。自然老化有效，不应写成“老化机制失效”。
- 480 的单位是 1000 TU；`idle > floor(480×1024/1000)` 首次在 492 命中。不能把它写成漫游后精确等待 480 秒或 492 秒，计数可能重置。HE_AX/TWT 已编入且当次 bitmap 为零，`ps=1` 不支持“本版因省电而跳过踢除”。
- k=0 仍失败，足以否定“关闭 k 已修复”以及“开启 k 是此机制的必要条件”；不能推导 k 对触发频率完全没有影响。
- 043 的字段是路径观测，并非站点世代的原子快照；`submitted=1/submit_rc=0` 只证明提交。多条匹配记录和自然删除后的切换支持直接机制，但尚未完成保持旧条目不变的干预对照，也未排除后续另有卸载、交换芯片或 GS7 故障。

根因文档中的“已确定阻断连接的驱动机制”在上述范围内合适；“根因全部查明”“桥转发必然修复所有漫游”则过强。社区 mac80211 提供架构先例，DSA 提供另一故障层的参考，两者均不构成本机修复验收。

**A 的首要缺口是执行工具，而非 UCI 字段是否存在。**

这不是已确认有 ucode 内置私有 ioctl 替代外部工具的路径。[mtwifi-cfg-ucode 包依赖](/home/illya/workspace/router/ax6000/sources/immortalwrt-mt798x/package/mtk/applications/mtwifi-cfg-ucode/Makefile:36)没有显式列出 `wireless-tools`；[Build 19 完整配置](/home/illya/workspace/router/ax6000/firmware/dev-build19-roam-diag/ax6000.config:2049)为 `# CONFIG_PACKAGE_wireless-tools is not set`；[该工具包安装规则](/home/illya/workspace/router/ax6000/sources/immortalwrt-mt798x/package/network/utils/wireless-tools/Makefile:82)才建立 `/usr/sbin/iwpriv`。这些本地证据与任务给出的“本机此前 command -v 未找到”一致，构成实质缺口。它们仍不能排除路由器另有手工安装、不同 PATH 或其他已验证接口；本轮没有对此做现场确认。

主线程后续如获准检查，只需先只读核对本机文件/包清单、实际服务 PATH、已部署脚本版本及既有执行错误；不能把 `iwinfo` 可用视为 `iwpriv` 可用。若确认缺失，A 应改称“补齐兼容调用工具后可试的配置缓解”，重新计算准备与维护成本；不能继续只写 UCI 再把无效果判为 RSSI 机制失败。修正包依赖或执行错误处理也属于后续独立改动，本报告未实施。

还需修正“运行时 hook”带来的无中断暗示：[config.uc:167](/home/illya/workspace/router/ax6000/sources/immortalwrt-mt798x/package/mtk/applications/mtwifi-cfg-ucode/files/usr/share/ucode/mtwifi/config.uc:167)的 setup 会遍历相关接口并 ifdown，再 ifup、应用 hook。setter 本身支持运行时设置，不代表经完整无线 setup 应用 UCI 就不清关联状态。若只能通过重载应用参数，须重建起始位置、重新漫游；重载后的即时恢复不计作 A 的效果。

**赞成有条件先试低 RSSI，但不赞成直接推荐固定 −85，更不赞成以此取代 B。**

[ap.c:4030](/home/illya/workspace/router/ax6000/sources/vendor-mt79xx-7.6.7.3/source/mt_wifi/embedded/ap/ap.c:4030)要求 `Rssi_Updated && 非零阈值 && RTMPAvgRssi()<阈值`。标志在 `mgmt_entrytb.c:952` 初始化为 FALSE，在 MT7986 的 [RssiUpdate 路径](/home/illya/workspace/router/ax6000/sources/vendor-mt79xx-7.6.7.3/source/mt_wifi/hw_ctrl/cmm_asic.c:2906)读取固件 RSSI 后置 TRUE。它不是“刚从该 STA 收到新帧”的时间戳；TRUE 也不保证样本新鲜。`RTMPAvgRssi()` 使用驱动各链的 AvgRssi 计算，不能未核对显示口径就把列表中的一个 dBm 值当作该条件的精确输入。

反证尤其具体：[第一轮故障快照](/home/illya/workspace/router/ax6000/research/evidence/roam-20261108-163317/final-recovered/failure-164014.txt:6)显示平板 −83 dBm，第二轮才显示 [−92 dBm](/home/illya/workspace/router/ax6000/research/evidence/roam-k-off-20261108-1735/failure-confirmed-snapshot/failure-confirmed.txt:10)。若 −83 接近维护函数实际均值，−85 不会触发。两者并非必须冲突，它们属于不同漫游轮次；它们共同否定了“旧平板总在 −92，所以 −85 足够”的外推。调得更严格会影响更多仍在覆盖边缘正常使用的设备。

该 setter 写的是 `MBSSID[apidx].RssiLowForStaKickOut`，作用范围是目标 BSS 的符合条件站点，不能限成只踢平板。固定端一次约 −59 不代表该 BSS 的所有其他终端都安全。所读条件没有要求连续多次低 RSSI、保持时长或检查 GS7 是否可接入；不能承诺它会把客户端顺利送到 GS7。只开 kicklow 而不改关联拒绝门限时，客户端也可能重新连回 AX 并再被踢。

A 进入后续小实验的前提与判据应为：

1. 调用工具、目标 5 GHz BSS 映射、实际 setter 成功及恢复旧值的接口可确认；仅修改一个踢除门限，保持关联拒绝门限、k/v/r、其他 AP 和老化值不变。
2. 确认当前业务可接受目标 BSS 的边缘覆盖收缩，并有足够替代覆盖。−85 可作为有出处的起始候选，不能预定为最终值；若可靠证据显示故障前提从不命中，不应无限调严来追求表面成功。
3. 记录真实 RSSI 踢除原因、条目删除、时间及后续新业务成功；043 已有 `cause-rssi` 插桩，但当前诊断关闭，本轮没有开启。要区分未执行 setter、未满足条件、进入踢除但未实际删除、删除后业务仍失败。
4. 重新发生 AX→GS7 和 GS7→AX，观察同 AP 使用、边缘静止使用及睡眠唤醒。只有缩短故障窗口且未引入可观察断连/来回关联，才称为“在已测条件下缓解”。不再复现但没有踢除/位置证据，只能记为结果未定。
5. 出现正常终端误踢、反复重连、覆盖缺口即停止并恢复记录的旧值；若旧值为 0，须确认运行值也恢复为 0。只删 UCI 项或看 DAT 不足以证明恢复。已经被踢的关联不会因门限回退自动恢复。

**按目标排列后续方案，而非把 A–F 当作必须逐项尝试的清单。**

若目标是暂时少受影响，先解决 A 的只读可用性核验；工具可用且覆盖条件允许时，A 是第一项单变量缓解。A 不可用、无命中或副作用明显，应结束此路线的当前尝试。若用户暂时不能接受诊断固件，才考虑 C，接受其仍有中断和睡眠终端代价。无须为等 A/C 成为“通用修复”推迟 B 的设计。

存在更小的人工恢复干预：在确认平板仍在 GS7 时定向 `DisConnectSta`。它可以清理目标旧关联，影响范围可能比 BSS 级 RSSI/老化调整小；但也依赖可用的调用接口，且不是持久方案。[ap_cfg.c:22750](/home/illya/workspace/router/ax6000/sources/vendor-mt79xx-7.6.7.3/source/mt_wifi/embedded/ap/ap_cfg.c:22750)按当前 MAC 查找并发起 deauth，查不到也返回 TRUE，故返回成功不等于实际删掉条目。不能传广播地址，不能把一次位置查询当成后续自动删除的竞争保护。自然老化证据已足够，本次没有必要为了重复证明“删除能恢复”再要求现场操作。

若目标是消除已定位的数据路径黑洞，B 为首选因果实验和修复候选；通过机制实验后继续验证完整业务与性能。只有 B 的实测 CPU/吞吐代价不可接受，才提升 D 的优先级。若 GS7 能提供可信、新鲜且可绑定关联身份的移动事件，E 才值得前移。若 vendor 数据路径无法受控、维护代价不可接受，或 B 的完整验收不通过，再独立评估 F；必须保留当前 MTK U-Boot 布局约束，不能把不兼容布局迁移当作普通升级。

**B 没有已发现的架构性否决，但目前有进入实机 ON 实验前必须落实的阻断项。**

第一项是可证明的授权范围。`ap_rx_pkt_foward()` 的 `SST_ASSOC/同 wdev` 不等于完整授权检查；原函数的源 MAC 查找只有命中后才检查 `PortSecured`。必须结合上游 RX 校验、实际 RX WCID 与源 MAC 一致性、当前 wdev、站点类型及既有安全补丁确定允许条件。本地 [041 端口安全补丁](/home/illya/workspace/router/ax6000/sources/immortalwrt-mt798x/package/mtk/drivers/mt_wifi/patches-7673/041-fix-cmm_data-header-translated-port-security.patch)将头转换路径的授权状态绑定到 RX peer，不能只读未打补丁的原始函数来设计新入口。当前材料并未证明所有 RX 形态的此项审计已经完成；也不能据此断言现场存在可利用的源伪造漏洞。

第二项是“交桥”的实际含义。[cmm_data.c:3608](/home/illya/workspace/router/ax6000/sources/vendor-mt79xx-7.6.7.3/source/mt_wifi/embedded/common/cmm_data.c:3608)在 `to_os=TRUE` 后调用 `announce_802_3_packet()`，但其 [rt_profile.c:1822](/home/illya/workspace/router/ax6000/sources/vendor-mt79xx-7.6.7.3/source/mt_wifi/os/linux/rt_profile.c:1822)仍有 `ra_sw_nat_hook_rx`、WHNAT 分支。[Build 19 配置](/home/illya/workspace/router/ax6000/firmware/dev-build19-roam-diag/ax6000.config:6002)包含 FAST_NAT/WHNAT/WARP 支持；编入不证明当时流量使用它们，却足以要求核查。因此必须区分“允许继续上送”和“实际进入 bridge 并按 FDB 发出”。只改布尔值、只看日志变成 1/0，不能直接宣告 B 生效。

第三项是模式切换与快速/卸载路径的关系。必须知道目标流是否绕过改动点、哪些缓存可能保存旧出口、如何让开关对目标流生效并关断。若开关只能依靠全局重载或清 STA/FDB 才生效，便不满足本次候选的因果实验要求。若需要使目标流的快速缓存失效，需将其写入模式切换设计，在 ON/OFF 下对称处理，并增加“保持 OFF 但做同等失效处理”的对照，分离清流本身的效果。无法做到时，先保留为实现阻断，不能用刷新后的正常业务替代因果证据。

第四项是观测与修改范围必须分离。043 的 [mt_roam_diag_init 过滤器](/home/illya/workspace/router/ax6000/firmware/dev-build19-roam-diag/043-roaming-path-diagnostics.patch:364)是“源或目的任一 MAC 在列表中”，还限于未打标签 IPv4、指定 TCP 端口的 SYN/RST。第一轮因此也记录了固定端与第三台设备的流量。这适合诊断采样，**不适合直接作为 B 的转发许可条件**。实验必须独立判断精确的 A→B 或 B→A 双 MAC 对，且转发不能依赖诊断是否开启、日志限流是否允许或 TCP 解析是否成功。

这些是实现与实验放行条件；不代表今天已经写成、编译或验证。也不要求先获得 GS7 离网管理帧，才能设计这一最小干预。

**B 的最小范围应具体到以下行为。**

- 默认关闭；只匹配 `08:eb:21:f2:88:4d` 与 `6a:37:f7:8b:b8:da` 两端互为源/目的的普通数据单播，以及指定 AP/wdev。两端均须是符合要求的普通客户端上下文，源接收身份与授权可确认。目标 MAC 在实际试验中若改变，应重新确认对象，不扩大成任意客户端规则。
- 在现有拒绝逻辑全部完成后、`DuplicatePacket/CopyPacket` 之前，仅把原本同 BSS `to_os=0/to_air=1` 改为 `1/0`。`0/0` 拒绝不得覆盖，已上送路径保持原样。不能同时向桥和旧 WCID 发出，不能重用旧 WCID 强制指定桥回发目标。
- 覆盖该范围内的普通 L2 单播数据，包括单播 ARP、IPv4/IPv6、TCP 数据与 UDP；认证控制流仍遵循既有特殊处理。保留组播/广播、跨 BSS、WDS/A4/MWDS/APCLI、隔离等路径。VLAN 排除需要同时考虑帧内标签、skb VLAN 元数据、wdev 配置和站点动态 VLAN；`bridge vlan_filtering=0` 不等于所有这些条件均不存在。
- 保留 skb 的源/目的 MAC、正确入接口和正常 bridge TX 语义，确保源学习及同口 hairpin 工作。`hairpin=1` 是同 AP 互访的必要条件之一，不能替代对桥端口、netfilter/隔离规则、驱动回发行为的核验。若桥规则阻止业务，应分析原有策略，不为使实验通过而放开安全规则。
- 开关与 MAC 对配置应一致地发布，非法输入不得扩大范围，RX 中不引入会睡眠的锁或桥私有指针缓存；关断完成的语义应涵盖在途包和缓存。不能跨包长期保存站点指针或把 WCID 4 当成固定身份。若 `WH_EVENT_NOTIFIER` 生效，还需审阅原本在改写点之前递增的 `pEntry->tx_state.PacketCount`，避免未走空口仍按原路径计数。
- 为候选命中、拒绝原因、原/新决策、实际后续路径和关断状态提供有界观测。043 可以继续匹配握手，但不能单独证明 IPv6、UDP、ARP、聚合数据或持续业务已覆盖；无日志也不能当作路径未发生。

**B 的因果放行、长期放行和停止标准应分开记录。**

因果实验先在候选固件 OFF 状态重新建立“两端在 AX，随后平板去 GS7、固定端留 AX”的条件，复现相同失败。候选固件 OFF 若不能复现，不能算修复成功。实验窗口需留有老化余量，持续记录目标旧关联是否仍是原条目；发生删除、重关联、MAC/WCID 换代或终端位置变化，应结束该次可比窗口。

在旧条目仍在、桥 FDB 正确且其他状态保持可比时做 OFF→ON→OFF→ON。每段使用新的连接，关联四元组、seq/ack、目标分支、实际桥/wan 出口及应用结果；ON 期间还须完成实质数据传输。不得通过无线重载、清 STA、手工改 FDB、改 k/v/r、缩短老化来替代开关效果。若 ON 后立即有匹配回包和新业务成功、OFF 后同一旧条目再次截包、再 ON 恢复，便强力支持该干预切断了本次直接阻断机制。应在独立漫游轮次重复，而非只重复同一旧连接的重传。

开关的“回退”只恢复转发选择，**不会撤销 ON 期间产生的桥学习、邻居更新、连接状态或已经发出的帧**。因此 OFF 后未重现时，需核对 FDB、关联身份、老化、快速缓存与业务状态；该轮应记为不足以完成反向对照，不能直接否定旧条目机制，也不能跳过解释就宣布因果闭环。若必须清目标流缓存，应按前述对称处理及 OFF 对照记录，不能称为只改变一个布尔值。

生产候选需要另过以下可检查条件：

- **双向漫游与源学习：** AX→GS7、GS7→AX；返回后分别由两端主动发起业务；在平板首个合格上送源帧之后，桥应学习到 `rax0`，不能仍被快速路径遮蔽。还要记录返回但尚未发送源帧的短暂窗口，不能用“迟早会发 ARP”承诺零中断。覆盖两端同在 AX、同在 GS7、分别在两 AP 及往返后的状态。
- **协议与路径：** IPv4/IPv6、TCP 新建与持续数据、UDP、单播 ARP/邻居相关业务；广播/组播发现行为保持预期。确认普通 RX、头转换/聚合接收、实际启用的快速和卸载路径，覆盖冷连接与已运行的流。仅在停用卸载的固定条件下通过，可支持软件路径可行，不足以放行当前生产加速配置。
- **安全与范围：** 未授权源、隔离客户端、跨 BSS/VLAN、特殊转发模式和非目标 MAC 对不获得新增放行；允许的同 BSS 互访正常。没有重复转发、环路、误投其他接口或泄漏。未能覆盖的配置应明确不在修复支持范围，不能概括为“隔离已验收”。
- **稳定性与性能：** 没有新增驱动告警、崩溃、队列/内存持续增长或模式关断失败；测量同 AP 与跨 AP 的业务吞吐、时延/丢包、CPU/软中断及持续负载表现。性能比较须在同等诊断开销下进行，PHY 连接速率不是吞吐证据。当前没有用户业务容量预算和测量值，不能填写虚构百分比或评分；扩大使用前需把实际工作负载及可接受回退边界写明。

发现安全越界、重复/环路、非目标设备受影响、崩溃或无法可靠关断，应立即停止候选；出现 `to_os=1` 但没有实际出口/业务成功，应判该候选未通过并定位后续路径，不能继续以“社区就是这样做的”放行。若必须改动隔离、特殊路径或全局加速条件才能工作，先重新界定方案范围。预先保留有线管理入口及当前布局兼容的已知可用镜像；首级回退为关断并核验默认行为，必要时才恢复原固件。重启/回刷属于恢复手段，结束本轮因果实验；不顺带恢复成旧 k=1，不动 GS7、引导器或分区布局。

**各方案的实际取舍如下；“覆盖”同时区分射频服务范围与故障适用范围。**

| 方案 | 覆盖与漫游稳定性 | 性能 | 维护复杂度与异构 AP 依赖 |
| --- | --- | --- | --- |
| A：低 RSSI 踢除 | 收缩目标 BSS 边缘可用范围；仅缓解满足 RSSI 条件的旧 STA，也可能提前踢掉仍正常使用者。强信号漫游、冻结的高值不受保证，可能反复关联。 | 不主动改转发路径；重新认证、切换造成的业务中断可能抵消收益，不能把无线速率变高当成成功。 | 工具、hook、运行值和回退要维护；阈值需随环境/终端校准。无需 GS7 控制接口，但依赖可用替代覆盖与客户端选择。 |
| B：目标双 MAC 对交桥 | 不主动改变射频覆盖或踢 STA；直接处理选中数据路径，减少对离网通知的依赖。初版只覆盖两 MAC 和指定普通 BSS，不能外推全网或 GS7 内部路径。 | 可能增加 CPU/桥处理及改变卸载行为；仍可经无线回发。实际吞吐和时延未知。 | 需维护 vendor 补丁、授权/快路径及回退测试；不要求跨厂商事件协议，仍依赖桥和 GS7 正常转发。 |
| C：缩短 BssMaxIdle | 不调整射频门限，但更易断开静默/睡眠站点；只缩短符合空闲计数条件的等待，仍有黑洞窗口。 | 稳态数据路径不变；可能增加重关联和功耗。 | 参数应用、每 STA 复制值及回退要核验；无 GS7 事件依赖，覆盖影响可能比两 MAC 实验广。 |
| D：按 FDB 选择旁路 | 理论上只在目的移到其他端口时交桥；返回源学习、陈旧/未知 FDB、VLAN 与并发是核心正确性负担，不是一个可靠的“已离开”真值检测。 | 可保留更多同 AP 内部直转，但查询/同步/缓存也有代价；未实测前不能承诺优于 B。 | 桥接口、锁、对象寿命、模块许可和快速缓存协同复杂；不必有 GS7 控制协议，但依赖及时可信的 L2 学习。 |
| E：事件驱动定向清 STA | 精确可信事件可快速清旧状态；乱序、遗漏或延迟事件会漏清或误踢刚返回的关联。没有代际保护便可能恶化稳定性。 | 保留现有数据路径；误删会产生重认证与业务成本。 | 对 GS7 事件出口、认证、重放/乱序处理和关联身份绑定依赖最大；MAC-only 删除接口不足以原子验证新旧关联。 |
| F：换 mt76/其他镜像 | 可改变相关转发机制，也会改变无线行为和兼容性；最终取决于实际驱动、hostapd 与桥配置。覆盖、休眠/重连稳定性需重新验收。 | 无法从驱动名推断性能或加速可用性；需重新评估吞吐、CPU及硬件功能。 | 初始迁移成本最大，涉及 MTK U-Boot 镜像兼容、包/配置迁移及回退；长期维护收益取决于具体项目。保留 GS7 时仍需跨 AP 实测。 |

C 还有两处应收紧措辞：[BSS setter](/home/illya/workspace/router/ax6000/sources/vendor-mt79xx-7.6.7.3/source/mt_wifi/embedded/ap/ap_cfg.c:13989)只更新 BSS，`mgmt_entrytb.c:1418` 在新 STA 建立时复制到 `StaIdleTimeout`，修改和恢复都不能假定立即影响已有条目。DAT 解析的 0 回默认规则不能外推到运行时 setter，后者拒绝 0；恢复当前 480 应显式核对 BSS 及后续 STA 值。计数可重置、TWT 条件另有保护，故草案“最坏残留时间”“有界等待”须限定为适用站点持续满足空闲条件时的计数阈值，不是从漫游时刻起的绝对 SLA。

D 的 API 阻断是具体事实：[br_fdb_find_port](/home/illya/workspace/router/ax6000/sources/linux-6.12.112-roam-refs/net/bridge/br_fdb.c:242)要求 `ASSERT_RTNL()` 并 `EXPORT_SYMBOL_GPL`。RX 软中断不能直接加 RTNL；加 RCU 不能替代它；现场模块标记 PO，也不能默认可用 GPL-only 导出。桥侧协作方案必须解决合法接口和生命周期，不应把加一层包装当作规避导出限制的方法。若目的 FDB 仍是 `wan`，返回的平板流量又只在驱动内部转发而未触发源学习，简单优先 FDB 会制造反向错误。未经验证的 FDB 事件也不能直接升级为 E 的删站授权。

E 的竞争不能只靠用户态“再查一次”解决：查询后、删除前可能刚好重关联。现有 `DisConnectSta=MAC` 查找的是执行时的当前条目，没有携带“仅删除某一关联世代”的条件。长期自动化需让动作绑定可验证的旧关联身份并在执行点检查，或采用能提供等价保证的机制；目前未确认可用。历史 IAPP 不等于 GS7 有现成、安全、互通的事件接口；单独 L2 Update 只更新桥学习，本次桥 FDB 本来已正确。

F 也不应按名字验收。本地 mac80211 普通/fast RX 均有条件式内部转发，`DONT_BRIDGE_PACKETS` 才改变相应行为；OpenWrt 的 `ap_isolate` 映射、桥 hairpin 与安全策略需一起审查。MTK `NoForwarding` 的语义不同，不是无代码 B 开关。DSA 漫游补丁可以作为独立维护项评估，但不能修复已在 mt_wifi 中 `to_os=0` 的这一步。

**主线程草案需要的修订可以集中为以下事项。**

1. 将“UCI 路径已追到实际应用/现成配置可用”改为“源码调用链已追到外部 iwpriv；本机可执行工具和成功下发尚未确认，Build 19 存在缺包线索”。“不用刷固件”应附此条件。
2. A 加入第一轮 −83、第二轮 −92 的反证，区分显示 RSSI、驱动均值和 `Rssi_Updated`；补充 BSS 级影响、无已证实防抖及 setup 可能清状态。社区 −85 只是示例。
3. B 明确精确双 MAC 对，禁止复用 043 的任一端命中过滤器；增加实际 RX 身份授权、VLAN 元数据、043 观测范围不足及 `to_os` 后仍有卸载钩子的约束。
4. 将 B 的“开关可回退”限定为路径策略回退；补充学习/连接/缓存不可逆状态、目标流缓存对照，以及未能 OFF 再现时的未定分类。机制通过与生产通过分开。
5. C 删除无条件“最坏等待有界”的暗示，写明新 STA 才复制、睡眠副作用及运行时 0 不可作默认回退。
6. E 补上 MAC-only 清理的查询/执行竞争；D 的桥侧封装不得被写成已经解决 RTNL/GPL-only 问题。
7. 统一主文、社区文和新草案的推荐口径：快速缓解为 A 的条件式试验；长期修复/因果验证为 B。不要同时留下“下一步直接实施 B”与“现成 RSSI 已可直接先用”两项无条件建议。
